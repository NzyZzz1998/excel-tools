# v1.2.0 新工具窗口：本机 DPI 与布局复核

2026-10-11，源码实测通过，本次不修改产品代码。

使用打包环境的 Python 3.12.8 / Tk 8.6.15，先调用 `enable_windows_dpi_awareness()`，再创建 `Application`，通过主窗口入口创建 `TableToolsWindow`。Win32 系统 DPI 为 96，进程为 System aware（值 1），Tk 为 96.047 DPI，屏幕 2560 × 1440。源码 SHA256 绑定见 [JSON 记录](dpi-validation.json)。

| 场景 | 实际结果 |
| --- | --- |
| 默认 900 × 760 | 文件选择、添加/移除来源、输出目录、读取表头、开始、停止、打开结果、状态及日志均在窗口内，窗口未超屏 |
| 最小 760 × 700 | 上述控件均可见，错误日志保留可读高度及垂直滚动入口，窗口未超屏 |
| 长路径与大量记录 | 12 个合成来源、超长中文路径、8 组多行合成错误未挤出主操作和状态；列表及日志可滚动 |

使用 `PrintWindow` 截取本探针 PID 创建的透明窗口，PNG 为本轮实时生成，未捕获桌面或其他进程。已目视核对 [默认窗口](dpi-900x760.png) 和 [最小窗口](dpi-760x700.png)。其中来源、路径和错误均为合成界面状态，未读取真实工作簿，不代表处理任务运行结果。

可复验脚本：[check_dpi.py](check_dpi.py)，仅依赖标准库和项目源码。本次验证实际 96 DPI，未覆盖 125% / 150% 等其他系统缩放或不同屏幕尺寸，也尚未针对最终 EXE 重跑。未发现本机裁切，因此保留已冻结 GUI 源码 `459d672dd94668fc596cc938e304154e8840543d7835df36c9d4abec03027627`。
