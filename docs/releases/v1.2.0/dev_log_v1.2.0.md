# v1.2.0 开发日志

## 2026-10-11 合同与并行实施

承接开源调研后“继续吧”，本轮范围冻结合表＋两种拆表。独立角色分别负责流式IO、GUI、黑盒测试；根任务负责数据编排、集成、文档与实际验收。根基线b48e97d，版本v1.2.0为建议编号。

关键决策：维持标准库运行时；SST与分组采用磁盘SQLite；值/数字格式输出，公式拒绝；数据区域合并拒绝；1900/1904混用拒绝；先写完整临时任务再排他发布。源与既有结果不改。新UI独立Toplevel共享一个Tk解释器，原页任务与新工具互斥。

已验证：180项测试通过，包含旧115项、IO17项、数据编排28项、新GUI13项与根窗口7项；本机DPI96原生窗口默认/最小可用。隔离便携自检已覆盖旧引擎与三种新任务。候选源码和EXE身份见acceptance/candidate-identity.json。

发现及处置：IO在最后一次保存进度回调后遗漏取消检查，已先以反例失败后修复；CR保真反例经核对发现是openpyxl生成夹具在无lxml分支将CR直接写入XML导致源文件先正规化，夹具改为合法&#13;且先读回确认后通过，未降低产品断言。旧GUI测试硬编码v1.1.1已按本轮版本更新。文档源码运行最低版本改为Python3.11，实测/打包3.12.8。

大表前置：旧默认拆分填充结果尾行A757636:G757636保留横向合并，新工具执行正确拒绝且清理整批。复制到本轮忽略目录后调用已有all_merges=True，实际拆1处、填6格，耗时205.958秒；此为合法输入准备，不能算新工具性能，也不能称原始104MB直接处理成功。所有表头后非空行包含汇总尾行都会保留。

完成验证：757635行×22列的已展开月表副本，拆8份141.138秒/30.79MiB RSS，合回143.070秒/30.64MiB，按列拆29份151.967秒/46.40MiB。源与三组输出全量解码后值/类型/数字格式摘要一致；38份表头及29份组别归属附加核验通过。10万条唯一长字符串、56MB未压缩SST压力通过（11.526秒/32.20MiB RSS）。性能测量、核验和输入准备分别计时。

月表原始openpyxl摘要曾不一致：其inlineStr分支没有解释ST_Xstring。实际Excel只读对照F246相同，六种纯合成转义再证明语义；修正独立oracle为有存储类型约束的单遍解码，不调用应用读者。保留原失败JSON，另做三个oracle回归；404.611秒全量复验通过。所有运行模块/冻结候选均未因该校验器问题改动，无需重建候选或重跑有效性能数据。

候选在自动测试通过、源码冻结后与剩余大表内容核对并行准备；最终交付等M4与M5全部通过后才确认。最终事实源acceptance/report.md及candidate-identity.json；本轮只交付本地候选，未提交/推送/tag/Release，正式下载仍v1.1.1。
