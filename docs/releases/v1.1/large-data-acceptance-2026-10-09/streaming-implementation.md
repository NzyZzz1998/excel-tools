## 处理方式与资源范围

以 ZIP 中工作表 XML 的**未压缩大小**选择路径：小于 8 MiB 保留原完整 DOM 路径；达到阈值时逐行落盘。阈值限制小表路径的输入规模，避免压缩率掩盖大 XML，也便于让现有小表处理与测试继续作为对照；它不是 Excel 容量上限或性能承诺。

大表第一遍使用标准库 `xml.dom.expatbuilder.ExpatBuilderNS`，即 minidom 使用的解析器。完整行写入临时文件后立即从树中移除并释放。内存保留工作表非行骨架、行号与文件偏移索引、真实格范围，不保留全部单元格树。

第二遍按行号回放，补齐拆分所需的缺失行，按起始行维护活动合并区域。锚点从原行脱离前保存有效命名空间及 `xml:space`，只在区域活动期间保留。原根及 sheetData 上下文用于重新解析单行。文本 CR、属性 CR/LF/TAB、CDATA、前缀遮蔽及空格规则继续使用已有解析与序列化逻辑。保留的横向合并延迟逐项输出，不为矩形拆分额外累计大 mergeCells 树。

所有转换后的工作表暂存到磁盘，全部工作表通过后才独占创建结果。未修改 ZIP 部件也分块复制，避免共享字符串、图片等部件整体读入内存。源文件不写入。内存仍与单行大小、非行 XML 元数据、活动锚点和行索引有关；临时磁盘空间与转换数据量有关，不承诺任意大小文件。

## 保留与明确拒绝

- 公式、vm/cm/extLst 及被合并掩盖的独立内容仍拒绝整文件；只处理本次选中区域。后续行或后续表拒绝时不生成结果。
- 行排序、格排序、缺失行、矩形默认横向保留、全部拆分、维度覆盖真实格和剩余合并保持原规则。
- 大表在知道选中合并前只记录坐标结构错误；若没有匹配区域则原样保留，与原路径一致。
- 新增明确拒绝：两个合并区域相交，且至少一方本次将拆分。原实现对这类异常结构的填充值依赖合并列表顺序，可能重复覆盖。两条路径现在共同按起始行及活动区域检查，以中文报告两个范围；空白、同锚点和完全重复区域也适用。无匹配或仅无关保留横向区域相交仍保持原样。真实日明细不存在此类相交。
