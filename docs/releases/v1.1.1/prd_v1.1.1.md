## 用户流程和异常

- 空闲选择文件为下一次“开始处理”准备；若有旧任务失败或待处理项，界面清楚显示旧任务恢复仍可用。
- 开始/恢复期间文件与选项不可更改，当前文件计时从 started 事件开始；阶段通知不改变最终成功/失败判定。成功、无需处理和错误仍以引擎最终返回为准。
- 停止和运行中关闭仍等待当前文件安全完成，只暂停后续项，保留窗口查看结果；阶段或计时更新不能覆盖停止请求。结束后停止计时并保留最终信息。
- 输出完整前不使用 `.xlsx/.xlsm` 正式结果名。被 OS 终止可能留 `.part`，不自动清理别的进程/旧会话文件。正常重试独立生成结果，不读残片恢复。
- 清理失败不得掩盖真正写入失败；用户看到原始技术原因及自己的残片路径。不得为清理而关闭外部进程或删除已有结果。
- 多个进程同时处理同一输入，也必须分别取得未占用的正式名称；不能以覆盖式替换来实现发布。

## 工程与可运行表达物

引擎新增可选 `process_file(..., progress=None)`，保留原三参数调用。回调参数为字典：`phase`（reading/filling/saving）、`sheet`、`completed`、`total`、`unit`（rows/bytes）；未知字段值为 None。阶段起止可即时报告，中间更新节流。工作线程只发 `('progress', file, detail)` 队列事件，Tk 主线程更新控件和计时。保存完成后才返回最终路径。
