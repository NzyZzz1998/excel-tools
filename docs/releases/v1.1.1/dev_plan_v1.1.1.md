# v1.1.1 开发计划

事实源：[PRD](prd_v1.1.1.md)；[progress](progress_v1.1.1.md)；[dev log](dev_log_v1.1.1.md)。基线 `4e013c4`，用户确认前三项改进和 v1.1.1 版本。没有扩大至性能重构或其他 review 候选。

| 任务 | 合同 | 负责人/文件 | 完成标准 |
|---|---|---|---|
| T-11 | F-11 | 引擎代理：excel_unmerge_fill.py；GUI代理：excel_unmerge_gui.py；对应测试 | 可选进度兼容原调用、节流、真实阶段/计时、文件计数正确，输出语义不变。 |
| T-12 | F-12 | 引擎代理：引擎及保存回归；质量代理：独立故障探针 | 完整后不覆盖发布、碰撞/权限/写入失败/清理失败/中断均保持原及旧结果，失败原因可追踪。 |
| T-13 | F-13 | GUI代理：GUI及窗口测试 | A/B选择恢复序列，实际目标清楚、下一次选择不丢、原快照/暂停保持，最小窗口可用。 |
| T-14 | F-14 | 主代理：版本文档、集成、打包；独立代理审查 | 版本1.1.1，源码全套回归、独立探针与自建窗口检查通过，冻结后构建独立便携候选并核验。 |
| T-15 | 用户后续明确授权与原条件发布授权 | 主代理：README、示例SVG、提交/推送/发布/公开；质量代理：公开适宜性审查 | README主张有证据，图示宽/窄屏可读；当前与历史无已识别的敏感业务内容/凭据；验收完成后提交推送、发布同源v1.1.1便携包，下载复核并核对远端public状态。 |

先并行实现引擎和GUI，使用PRD的事件合同连接。两者完成后运行一次完整测试，故障或新改动才重开受影响回归；再冻结源哈希、独立审查与实际包验收。质量代理不与实现代理共同修改同一文件。开发过程写dev log，状态只写progress。

具体风险：Windows rename与POSIX覆盖语义不同，必须选不覆盖方式；清理出错可能遮蔽原错误；每行发事件可能大量积压；停止文案可能被计时覆盖；恢复对象切换可能破坏下一次文件选择。分别以相关回归和独立探针作完成条件，失败不打包。

本地包使用独立 dist 子目录与新版本ZIP，不覆盖v1.1；运行探针只操作自己创建并识别的实例。源/已有业务输出不可覆盖。无必要进行无关重构或重复全量业务扫描。
