# 强制终止写入阶段的边界

证据状态：已确认；建议严重度：Minor。它是异常退出恢复的改进项，不等于已有安全停止按钮失效，也不是源文件损坏。

`excel_unmerge_fill.py:646–675` 直接以最终的 `_拆分填充.xlsx` 文件名独占创建并写 ZIP；`676–678` 仅在 Python 能执行异常处理时删除本次输出。操作系统强制结束进程后没有机会进入清理分支。

[可复现脚本](probe_hard_stop.py) 创建不含业务数据的最小 OOXML 包，先生成一份有效结果，再启动它自己创建的独立 Python 子进程。在新结果的第一个 ZIP 成员开始写入并刷新后，父进程只终止该子进程。不是操纵用户应用，也不是磁盘损坏或断电实测。同步点用于准确定位写入区间，不改变最终输出的命名和清理实现。

[执行记录](hard-stop-result.json) 确认：

- 源文件及先前有效结果 SHA256 不变。
- 本次 `_拆分填充_2.xlsx` 留下 45 字节，ZIP 无效，文件名仍像正常结果。
- 再次处理生成有效 `_拆分填充_3.xlsx`，残留 `_2` 仍存在。
- 自建子进程已退出，无残留。普通异常和用户点击“停止后续处理”的语义不在此探针覆盖范围。

最小改进方向：先在结果目录写唯一 `.part`，完整关闭 ZIP 后再以不覆盖方式发布最终文件名。发布失败仍须保留源和已有结果，清理只针对本次创建的临时项。Windows 上需验证独占命名/发布竞争，不能用覆盖型替换函数悄悄改变“不覆盖”的合同。异常退出仍可能留下 `.part`，但不会伪装成完成的工作簿；自动清理其他进程的临时文件不应附带引入。

承接角色：引擎维护。输入：本探针、已有输出碰撞及故障注入测试。产物：独立小补丁和回归记录。最小验收：正常成功、同名碰撞、磁盘/权限失败、写入中强制终止，均不修改原文件和既有结果，未完成的结果不采用最终工作簿名。若不能保持上述不变量，则停止上线该补丁；可独立回退。当前 review 未修改产品代码。
